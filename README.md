# Итоговый дипломный проект "API-сервис для магазина"
Приложение Django REST framework для автоматизации закупок в розничной сети через REST API
## Что сделано:

- рефакторинг:
  - изменен вызывавший ошибки код, обрабатывающий входящие данные:
    - *проблема*: методы post и put класса BasketView на запрос в формате "application/json" выдавали ошибки
      - *решение*: в алогоритм парсинга тела HTTP-запросов включено ветвление в зависимости от содержания заголовка `content-type`, логика вынесена в функцию `get_request_items()`, функция включена в модуль `custom_validators.py` 
    - *проблема*: метод post класса ContactView на HTTP-запрос в формате "application/json" выдавал ошибку
      - *решение*: изменен код, делающий мутабельным QueryDict: `request.data._mutable = True` заменено на `request.data.copy()`, использующее `copy.deepcopy()` "под капотом"
  - изменен код, формирующий ответы на HTTP-запросы - для соблюдения единого стандарта сообщений об ошибках и соответствия протоколу HTTP:
    - добавлены коды ответов в `JsonResponse` там, где они отсутствовали, что влекло возвращение кода 200, не соответствовавшего сути ответа
    - введена валидация входящих данных с использованием сериализаторов Django REST framework в тех функциях, где она отсутствовала
- разработана административная панель
- оптимизация: с помощью `Celery` + `Redis` медленные методы (отправка email-уведомлений пользователю, загрузка прайс-листа из yaml-файла) выведены в параллельные процессы
- контейнеризация: приложение Django REST framework, база данных Postgres, PG Admin, Celery worker, Redis "упакованы" в контейнеры с помощью Docker, Docker-compose
- документирование: с использованием `drf-spectacular` сгенерирована интерактивная документация API-приложения:
  - [http://localhost:8000/api/docs/sw](http://localhost:8000/api/docs/sw "При запущенном приложении можно выполнять запросы")
  - [http://localhost:8000/api/docs/redoc](http://localhost:8000/api/docs/sw "Выполнение запросов невозможно")


## Запуск:
- создать файл `.env`, где прописать переменные окружения (образец: `.env.example`)
- запуск проекта на локальном хосте: `docker-compose up -d`
- создать суперпользователя: `docker-compose run --rm api_service sh -c "python manage.py createsuperuser"`
